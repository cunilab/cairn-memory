# Kinds and records

Every authored memory has a kind, title and summary. Include a reason except for a plain note. Add evidence, optional detail and relevant kind fields. For a correction use `supersedes`; for a declared contradiction use `contradicts`.

| Kind | Use it for | Example | Kind fields |
| --- | --- | --- | --- |
| Decision | A choice and why it was made | Use disposable schemas for integration tests | `context`, `alternatives`, `consequences` |
| Rule | A constraint to follow | Preserve existing migration files | `exceptions` |
| Gotcha | A verified failure and its remedy | Setup changed a different profile | `symptom`, `cause`, `fix` |
| Procedure | A repeatable sequence | Rotate a device credential | `steps`, `when` |
| Fact | A verified property | The server listens on port 3111 by default | `source` |
| Preference | An individual's working preference | Ask before replacing a provider | `example` |
| Note | Useful context without a more specific kind | Notes from a migration review | No kind-specific fields |
| Handoff | System-written continuity | Resume after the last test run | Generated by session processing |

Send `memory_get` an ID to see its scope, status, trust, timestamps and any links. [Tool arguments and compact responses](../reference/mcp.md#tools).
