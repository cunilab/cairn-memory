# Cairn Memory 0.1.8 release notes

Fix for a false `stale` found on the live 0.1.7 server, and every stale memory now says why. No schema change,
no new tools.

## What changed for users

- **False stale fixed.** A file named in plain prose with a leading dot directory, such as `.cairn/project.json`,
  was stored as the entity `cairn/project.json` (the leading dot was cut). No checkout has that file, so the
  session-start repo check marked the memory `stale` (`missing`) and could never revive it. The dot is now kept
  (`.cairn/project.json`, `.github/ci.yml`), and `./` prefixes are removed as before.
- **Stale is explained.** `stale_cause` (`feedback` or `missing`) is now in `memory_search` cards, in `memory_get`
  records, and in the `memory_feedback` reply while the memory is still stale. A `helpful` vote still cannot lift a
  stale that came from the repo check; the reply now tells you so instead of just returning `stale`.

## Breaking changes

None. Known limit: entities are stored when a memory is saved and there is no backfill. A memory saved by 0.1.7
or earlier that cited a bare dot-directory path keeps the wrong entity (`cairn/project.json`), so the repo check
cannot revive it. Save the corrected memory with `supersedes` set to the old id (its entities are derived again),
or `forget` the old one.

## Upgrade steps

1. Upgrade the server and the clients together. There is no migration and no data wipe.
2. On each machine run `cairn update`.
3. Run `cairn doctor` and check that every item passes.
