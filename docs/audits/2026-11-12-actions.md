# Delete and revoke confirmation task 4 — 2026-11-12

Delete and Revoke now ask before they change anything. Share, invite, and create-team do not.

## Sources

- Registry item `https://ui.shadcn.com/r/styles/base-nova/alert-dialog.json`, fetched 2026-11-12. It uses `@base-ui/react/alert-dialog` and the local button. No new package.
- Installed `@base-ui/react` alert dialog sets `role="alertdialog"`, keeps the dialog modal, and disables pointer dismissal. Escape still closes it.
- Delete calls `delete_for_account`, which hides the id, writes `memory_delete_retained`, and leaves the stored record. `crates/core/src/lib.rs` `delete_for_account` and `hide_for_account`.
- Revoke sets `revoked_at` on that member's active share. The owner still has the decision. `revoke_project_share` in the same file.

## What changed

- Added `apps/web/components/ui/alert-dialog.tsx` from that registry. The popup width is `max-w-[calc(100%-2rem)]` so a 320px page can hold it.
- Delete and Revoke open that dialog. Confirm is the only path that posts. The confirm button is `variant="destructive"`. A second activation while the request is running is ignored, and the button is disabled.
- A failed post stays in the dialog with the server text and does not remove the decision. A missing or revoked session still goes to `/`.
- Memory prose uses `overflow-wrap: anywhere` and keeps `white-space: pre-wrap`. Ids and commits stay `break-all`.
- `apps/web/lib/action-copy.ts` and `scripts/smoke_web.sh` check that the sentences describe a retained hide and a named revoke, and that they do not say the record is erased.

## Correction — 2026-11-12

The first draft of the revoke sentence said the console cannot undo a revoke. That was false: Share decision posts the share route, and both stores clear `revoked_at`. The sentence now says to share the decision again. The delete sentence is unchanged.

A successful delete now removes that id from the list before the reload, and the in-flight guard stays until the reload settles. An older reload cannot paint the removed decision back. If the reload fails after the hide, the page says the decision was hidden and not to delete it again. A failed hide still leaves the row and the dialog.
