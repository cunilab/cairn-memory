# 0.1.6 memory model and agent surface

Date: 2026-11-21.

## Context

v0.1.4 grew a large surface: 38 MCP tools, a Python hook, a file-store adapter next to
Postgres, 13 flat optional memory columns, a human review queue and several manual steps
(promote, verify, requeue). The 0.1.6 audit measured the cost: thousands of tokens of tool
text per session, double result channels, and work asked of people that the product direction
(personal use or a small team, automation first) rejects. Pre-release rules still apply: no data
migration or legacy repair. This ADR records the 0.1.6 decisions; the designs are in
[foundation](../specs/0.1.6-foundation.md), [agent surface](../specs/0.1.6-step3-agent-surface.md),
[capture](../specs/0.1.6-step4-capture.md), [retrieval](../specs/0.1.6-step5-retrieval.md),
[processing](../specs/0.1.6-step6-processing.md) and [web](../specs/0.1.6-step7-ux.md). It
supersedes the review, requeue and manual-promotion parts of [ADR 0014](./0014-memory-scopes-distillation-and-hybrid-recall.md)
and the file-store parts of [ADR 0003](./0003-server-authoritative-postgres.md).

## Decision

1. **Postgres only.** One schema `cairn`, one migration. The file-store adapter and the old
   migrations are deleted. pgvector holds the embedding on the memory row.
2. **A typed model of about 20 attributes.** Common fields plus one Rust enum of per-kind
   fields (`Fields`); a wrong field for a kind cannot be built and unknown keys are rejected.
   Usage counters live in their own table.
3. **Five MCP tools:** `memory_search`, `memory_get`, `memory_save`, `memory_feedback`,
   `memory_forget` (down from 38). One Rust tool table generates `tools/list`, the CLI verbs
   and the instruction text; instructions are sent once, in `initialize`.
4. **Rust hooks.** The Python hook is replaced by `cairn hook` in the client binary, with an
   offline outbox. No Python is needed on a machine.
5. **No LLM anywhere.** Distillation, linking, consolidation and ranking are deterministic
   rules. A contradiction exists only as a declared link or a consolidation result.
6. **A small local CPU embedding model** runs inside `cairn-server` for the semantic channel; no
   external API is called. Model choice: **TODO — pending the embedding experiment** (the
   benchmarks so far use a pinned all-MiniLM-L6-v2).
7. **Automation first, no human triage.** No merge, verify, review, requeue or discard control.
   Jobs retry with backoff; quarantined jobs are retried after an upgrade and after 24 h. The web
   reports and handles essential tasks only (tokens, setup, accounts, rename, export/import,
   forget).
8. **Global promotion across owners, with guards.** A project rule or gotcha whose near-identical
   twin (cosine ≥ 0.92) exists in another project of any owner yields one global copy, linked to
   both sources. Only project-scope rule/gotcha memories qualify, never personal ones; the copy is
   re-redacted and is withdrawn when fewer than two live sources remain.
9. **Telescopic layout.** Memory context is delivered in layers of increasing size: a bounded
   session brief, then search cards under a token budget, then `memory_get` for one full record.
   An agent pays for detail only when it asks. *(Interpretation of the owner's term; confirm.)*

## Alternatives considered

- Keep a second (file) store: rejected, one authoritative store is simpler and visibility
  filters run inside the vector scan.
- Keep 30+ tools, or merge them behind a router tool: rejected, the 5-tool surface is smaller
  and enough for the agent's real loop (find, read, write, rate, erase).
- LLM-based distillation or reranking: rejected for cost, nondeterminism and privacy.
- A hosted embedding API: rejected, no external calls.
- Manual promotion and a human review queue: rejected by the automation-first direction.
- Promotion only inside one owner: rejected, the point is sharing a lesson learned twice.

## Consequences

- **Breaking:** the database is recreated, server and clients must upgrade together, Python
  hooks are gone, and MCP tools drop from 38 to 5. See [release notes](../release-notes-0.1.6.md).
- Deterministic rules can miss or mistype notes; quality guards at save time mitigate this.
- The embedding model adds CPU and a model asset to the server image.
- Global memory is readable by every server user, so redaction and the source guards are the
  privacy barrier; it stays best-effort.
- No human can fix a bad automatic merge by button; they can forget a memory or correct it with a
  save that supersedes it.
- The web never compares with older versions; it reports current figures only.
