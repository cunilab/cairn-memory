## What held

At both widths the document `scrollWidth` stayed equal to the viewport. Login, the empty list, the member list, and the owner forms did not create a horizontal page scroll. The viewport meta is `width=device-width, initial-scale=1` with no `maximum-scale` and no `user-scalable=no`. Zoom is not locked.

Login inputs are labeled, `type="email"` and `type="password"`, and computed at 16px. Member email and team name are labeled. At 320 those inputs are 16px as well. Tab order on login is email, password, Sign in. On the owner detail it continues Projects, Log out, then each decision's Share, Revoke, and Delete. The focused email and member-email controls keep a visible ring (`outline` is `none`; the ring is a box shadow). Headings in the accessibility tree are one `h1` and, on a project, `h2` for Decisions, Team, and Owner actions. Login exposes `main` and `form`. Project pages expose `main`.

Wrapped prose in the long decision fits. Owner buttons wrap onto extra rows at 320 and stay inside the viewport. The member view still hides owner controls. The team 400 alert is the same desktop issue. Mobile does not clip it or change its `role="alert"`.

## Findings

1. **Unbroken decision text is clipped** (`apps/web/components/project-detail.tsx:164`, `apps/web/components/ui/card.tsx:14`). Severity: high.
   - **Evidence:** At 390 and 320 the long paragraph's `scrollWidth` is 854px and its client width is 326px or 256px. Computed style is `white-space: pre-wrap`, `overflow-wrap: normal`. The card is `overflow: hidden`. Page `scrollWidth` stays at the viewport width, so the extra text is cut off, not scrolled. Screenshot `09-owner-detail-320.png`. The spaced sentences wrap. The `UnbrokenToken_…` tail does not.
   - **Effect:** A memory that contains a long token is unreadable on a phone, and on any width where the token is wider than the card.
   - **Fix:** Add `break-words` on that paragraph. One class. Do not remove `overflow-hidden` from every card.

2. **The project name is a 19px-tall link** (`apps/web/app/projects/page.tsx:79`). Severity: medium.
   - **Evidence:** At 320 the "Cairn Demo" link measures 79×19. The Projects back link measures 45×20 (`apps/web/components/project-detail.tsx:120`). Buttons that use the default size are 32px tall (`apps/web/components/ui/button.tsx:23`).
   - **Effect:** The name is the only hit target for the card. A 19px row is easy to miss with a finger. This is a measurement, not a conformance certificate.
   - **Fix:** Make the card the link, or give the link vertical padding so the target is at least 44px tall. Leave the 32px buttons unless a later pass changes the shared button size. 32px is short of a 44px target and above a 24px floor. That part is a suggestion.

3. **Loading is not announced** (`apps/web/app/projects/page.tsx:69`). Severity: low.
   - **Evidence:** With `GET /api/cairn/projects` delayed, the text "Loading projects…" is a `p` with no `role` and no `aria-live`. The empty copy "No projects for this account." is also a plain `p`. Screenshot `04-projects-loading-390.png`.
   - **Effect:** Text appears in the page, and a screen reader that is not already on that line is not told that loading started or finished.
   - **Fix:** Put `role="status"` on the loading paragraph. Leave the empty copy as normal text under the heading.
