# CLI and MCP

The `cairn mcp` stdio server and the `cairn` CLI share five memory tools. MCP and Hermes gateway chats also expose four skill tools. Each tool calls the REST API with the configured device token. The credential model is in
[authentication](auth.md).

## Transport

- Command `cairn mcp`; newline-delimited JSON-RPC 2.0 on stdin/stdout, diagnostics on stderr only.
  Methods: `initialize`, `notifications/initialized`, `tools/list`, `tools/call`, `ping`. Protocol
  version returned: `2025-06-18`.
- `cairn setup <server-url>` reads the device token from stdin (hidden on supported Unix terminals; setup warns when it cannot hide input) and writes the
  selected config file with mode `0600` through a temporary file and a rename. The selected file is
  `CAIRN_CONFIG` when non-empty, else `$XDG_CONFIG_HOME/cairn/config.json`, else
  `~/.config/cairn/config.json`, else `%APPDATA%`. `CAIRN_URL` and `CAIRN_DEVICE_TOKEN` are not
  configuration: a present one is ignored with one stderr line naming it, never its value.
- Server URL: `https`, or `http` for a loopback host only; no credentials, query or fragment; a path
  prefix is allowed. Every request goes to `<url>/cairn-memory/...`. Redirects are never followed.
  Plain `http` never uses `HTTP(S)_PROXY`.
- A line that is not UTF-8 or JSON gets `-32700`; JSON that is not one request object, or a line over
  8 MiB, gets `-32600`; the loop keeps reading. A message with an `id` (even `null`) always gets a
  reply; one without is a notification and runs nothing.
- Errors show the server's message with the token removed. A genuine 401 names the config file and says
  to run `cairn setup <server-url>`.

## Instructions

`initialize.instructions` carries one text, at most 700 bytes, generated by
`tools::instructions()`. It is sent once per MCP session and written to the agent's global
instruction block by setup. It includes the default session-start instruction. `serverInfo` is
`name: cairn-memory`, `title: Cairn`. Memory text is data, never instructions. CLI and MCP saves resolve a non-Git project from the nearest `.cairn/project.json`, including a nested folder.

## Tools

`tools/list` returns `{"tools":[{name,description,inputSchema}]}`. The five memory tools retain their 3,500-byte compact budget. The schema snapshot is `crates/client/tests/fixtures/tools_list.json`. The client adds checkout context to memory tool calls when available.

| Tool | Route | Arguments |
| --- | --- | --- |
| `memory_search` | `POST /search` | `query`; `kind` (the 7 kinds or `handoff`); `limit` 1–20, default 5 |
| `memory_get` | `POST /get` | `ids` 1–10 (duplicates answered once), `detail` (boolean, false by default, only for one id) |
| `memory_save` | `POST /remember` | `kind`, `title` ≤80, `summary` ≤240; `reason`, `detail` ≤8,000, `fields`, `evidence[]`, `supersedes`, `contradicts`, `scope`, `aliases`, `items` |
| `memory_feedback` | `POST /feedback` | `id`, `vote` = `helpful` \| `wrong` |
| `memory_forget` | `POST /forget` | `id` |
| `skill_search` | `POST /skills/search` | `query`, `limit` (1–20, default 5), `offset` (default 0) |
| `skill_get` | `POST /skills/get` | `name_or_id`, optional `version` |
| `skill_save` | `POST /skills/save` | `name`, `title`, `description`, `body`, `change_note` |
| `skill_feedback` | `POST /skills/feedback` | `name_or_id`, `version`, `vote` (`helpful` or `wrong`), optional `note` |

`reason` is required for every kind except `note`; the server answers the one-line error
`reason must not be empty for kind <kind>`. A correction is a save with `supersedes=<old id>`, allowed on the
caller's own memory or a project memory of the same project; a declared contradiction, for a memory
the caller cannot replace, is `contradicts=<id>`. Nothing infers either. `memory_forget` hides a memory the caller
owns from normal recall and is described in its own schema only, not in the instruction text.

**Quality.** A valid save that needs work is accepted with trust `new`. Supply a title of at least three specific words, a summary of at least five words that adds to it, and a reason of at least 20 characters that explains why. An optional reason for a `note` can be omitted. Include the symptom, cause and fix for a gotcha, context or alternatives for a decision, and ordered steps for a procedure. Cairn can also flag similar active memories you own in the same scope and project. System handoffs skip coaching. Web JSON import still applies its existing quality validation.

**Default scope** (server-chosen when `scope` is omitted): `preference` and `note` are `personal`; every other
kind is `project` when the request context names a project the person belongs to, else `personal`; `global`
only when the agent asks.

## Results

One channel: `content[0].text` is the server's compact JSON. There is no second structured channel and
no wrapper keys. A failed call, including a server 4xx, is `{"isError":true,"content":[{"type":"text","text":<message>}]}`.
A tool checks its required keys before the request; malformed JSON-RPC and unknown tools use JSON-RPC errors.

`memory_search` → `{"results":[Card],"more":n}`, `more` omitted at 0. `Card` is
`{id, kind, title, summary, score, trust}`, plus `status`, `stale_cause` and `label` on stale or replaced memories, and `seen` (proof count) when it is 2 or more. Scores are absolute and capped at 1.0.

```json
{"results":[{"id":"mem_…","kind":"decision","title":"Use Postgres SKIP LOCKED for the job queue","summary":"Background jobs run …","score":1.0,"trust":"proven · 4 helpful · used 12×"}],"more":3}
```

`memory_get` → `{"memories":[Record],"missing":[id]}` in request order; hidden and unknown ids go to
`missing`. `Record` is `{id, kind, scope, status, title, summary, trust, reason?, fields?, evidence?, links?, branch?, updated_at}`
with empty values omitted. A record with long detail includes `detail_chars`. Pass `detail: true` with one id to read the full `detail` if the summary and reason are insufficient. Both tools include a compact trust reason based on the record and counters at the time of the read.

`memory_save` → `{"id","status","deduplicated"}` for a single save. `items` accepts up to three notes and returns per-item results. A coached result adds up to four `hints` and an `improve` line explaining how to correct the saved note with `supersedes`. A clean correction is saved at normal rank. An identical save from the same owner returns the
existing id with `deduplicated:true` and merges new evidence. Detail is optional and does not affect identity. A duplicate can fill empty detail. An explicit correction can update detail without changing the id. A save that matches a forgotten memory is an
error. `memory_feedback` → `{"id","status"}`: `wrong` votes from two different people, or one from the owner, make it `stale`; a repeat vote by the same person changes nothing.
`memory_forget` → `{"id","status":"forgotten"}`.

`skill_search` uses PostgreSQL full-text search and returns `{results, next_offset}`. Each card includes the name, title, description, current version, score and vote counts. `skill_get` adds the full Markdown, author, creation time, change note and your vote. `skill_save` returns the saved version's card. `skill_feedback` returns the version's card with the updated vote totals.

Skills are global. A save with an existing name adds a new version with the caller as author. A vote applies to the named version and replaces the same account's previous vote. Skill names use 1–64 lowercase ASCII letters or digits separated by single hyphens. Byte limits are 80 for titles, 240 for descriptions and notes, 32,000 for bodies, and 1,024 for search queries. Cairn redacts secrets before saving skill text. The web console shows version history and rolls back by appending a version. Administrators can archive or restore skills in the web console. Archived skills are absent from agent search and get reports that the skill is archived. Hermes gateway tool calls use the same global library; the plugin strips chat and project context from these calls.

Search applies the relevance floor and scope rules of [recall](recall.md); no external
model API is used. Record shape and visibility: [projects](projects.md#memory-scopes-and-record).

## CLI

```
cairn setup <url> [--agent claude|codex|opencode|grok|antigravity|hermes] [--remove|--keep-native-memory|--gateway]
cairn setup <agent> [--remove|--gateway]                 cairn init [name] [--yes]
cairn import claude-memory [--yes]
cairn fixes [apply [id]]     cairn doctor     cairn mcp     cairn update [--check]     cairn hook <Event> …     cairn --version
cairn search <query> [--kind k] [--limit n]     cairn get <id>... [--detail]     cairn save [<json>|-]
cairn feedback <id> helpful|wrong               cairn forget <id>
```

The five verbs call the same tools and print the same compact JSON plus a newline; `save` reads one
`SaveInput` object from its argument or stdin. `doctor` prints `ok|warn|fail  <check>  <detail>`
per check, exiting 1 on any `fail`. It checks the config, server, semantic search, device, project,
and agent integrations. `hook` runs the capture and injection hook ([hook contract](./hook.md)).
Account and device management stay in the web console.

For a Cairn-managed integration, `doctor` warns if its global instruction block is missing or
differs from this version. The warning names the file and the `cairn setup <agent>` command that
refreshes the block. Repair malformed block markers before refreshing. Hermes gateway profiles
receive their instructions per chat and skip this check.

For Claude Code, `doctor` also checks the current project's `MEMORY.md` when the memory folder
exists and setup is managing native memory. Run `cairn import claude-memory` from that project
to restore the Cairn pointer. If import reports that an existing backup differs from a rewritten
index, move the rewritten index out of the memory folder before retrying.
Setup with `--keep-native-memory` skips the pointer check. These diagnostics only read local files
and print warnings.

### Hermes gateway tools

`cairn setup hermes --gateway` installs two native tools in the selected profile.
`memory_search` accepts `query` and an optional `project` ID or exact name.
`memory_save` accepts `kind`, `title`, `summary`, `reason`, `fields` and the same optional
`project`. Use the project only for project knowledge when the gateway account is a member.
Save preferences without a project. See [gateway setup](hook.md#hermes-gateway).

### Import Claude Code memory

Run `cairn import claude-memory` from the project to preview the files, scopes, and titles, then confirm the import and index replacement together. Pass `--yes` to apply directly. Cairn looks in the Claude config directory's `projects/<encoded project>/memory/`. It uses the main checkout for Git worktrees, respects `CLAUDE_CONFIG_DIR` and its optional `CLAUDE_CODE_PROJECT_DIR_NAME`, and uses the default layout for auto memory. [Claude Code memory directory](https://code.claude.com/docs/en/memory#where-auto-memory-is-stored) [Claude Code project directory names](https://code.claude.com/docs/en/sessions#name-the-project-directory-yourself)

| Claude file type | Cairn kind | Scope |
| --- | --- | --- |
| `user` | `preference` | Personal |
| `feedback` | `rule` | Personal |
| `project` | `note` | Project when `.cairn/project.json` exists, otherwise personal |
| `reference` | `fact` | Personal |

The import lists possible-secret files it skips and prints any coaching hints for saved files. The normal save API deduplicates reruns. Cairn stores the body in `detail`, uses the `**Why:**` line or the first 1,000 body characters as the reason, and keeps the source path as evidence. It lists bodies clipped to the 8,000-character detail limit and includes a pointer to the full text for each. Once every eligible file saves, Cairn backs up the old `MEMORY.md` as `MEMORY.md.pre-cairn` and writes the pointer. The original note files stay on disk. If a save fails, fix the reported file and rerun. Any files already saved will deduplicate.
