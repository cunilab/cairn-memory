# 0.1.6 Step 7 — Web console UX

Companion to `0.1.6-step7-web-hardening.md` (W§). That spec fixes the plumbing (six pages, `/stats`,
generated types, proxy); this one fixes **what each page says and does**. Where they disagree,
this spec wins on UX and lists the change in §9. Design system unchanged: shadcn/ui in
`apps/web/components/ui`, current theme tokens, Geist, lucide icons. No new UI dependency.

## 0. Product frame and decisions

The person opens the console to answer one of three questions: **is Cairn working, is it worth it,
and what did it do on its own?** Plus a handful of chores (token, setup, rename, export/import,
forget, password). Everything else is automatic and only *reported*.

| # | Decision | Why |
|---|---|---|
| U1 | Nav order: **Dashboard, Memories, Activity, Projects, Graph, Settings**. Sidebar label "Overview" becomes "Dashboard". | Ordered by how often each question is asked; Graph is exploratory. |
| U2 | Dashboard leads with one current-only sentence of value ("Your agents made 812 memory lookups in the last 30 days; 94% found something relevant. Cairn delivered ~24,300 tokens of memory context."), then the usage chart. No grid of equal stat cards at the top. **The web never compares with older Cairn versions** (no baseline, no old→new figures). | The value story is the reason the page exists; the chart is the one memorable element. Owner decision. |
| U3 | Every number that is an estimate says so in place (`~`, "estimated", tooltip with the method). Bench figures are labelled "benchmark", live figures "your usage". | Trust: tokens are bytes/4. |
| U4 | Zero human-judgment controls: no merge, verify, triage, feedback, requeue or discard buttons. Jobs are read-only (retries are automatic). Step 7 **removes** the admin requeue/discard routes and buttons. | Owner direction; overrides W3's admin requeue/discard (§9). |
| U5 | Kept actions: create/rotate/revoke device token, copy setup command, rename project, transfer ownership, export, import, forget memory, change/reset password, register account (admin). Each is one dialog with an outcome toast. | The essential-task list. |
| U6 | First run is a checklist on the Dashboard, not a separate wizard route. It disappears when the first capture arrives. | One less page; the dashboard is where people land. |
| U7 | Memory detail is a **Sheet** (right side, full screen on phones) reachable from Memories, Graph, Activity, Projects and the Dashboard; URL `?memory=<id>` so it can be linked. | One detail surface everywhere. |
| U8 | Filters live in the URL (`?project=&kind=&status=&branch=&q=`). | Shareable, back button works, no hidden state. |
| U9 | Device health is shown where tokens are managed (Settings › Devices) and summarised on the Dashboard only when something needs action. | Report problems where they are fixed. |
| U10 | Timeline wording: Cairn is the subject ("Cairn merged 2 duplicate memories"), past tense, counts first. | Makes the automation visible and legible. |

## 1. Information architecture

```
/login
/dashboard            value, health, usage, needs-attention, first-run checklist
/memories             filterable table  ── ?memory=<id> opens the detail sheet
/activity             tabs: Timeline (automatic actions) · Audit log · Jobs
/projects             list
/projects/[id]        tabs: Branches · Stale · Members   + Rename, Transfer
/graph                canvas (existing) → node opens the memory sheet
/settings             tabs: Devices · Account · Data (export/import) · Accounts (admin)
```

Sidebar: six items with the existing icons (Dashboard `LayoutDashboard`, Memories `Brain`,
Activity `Activity`, Projects `Folder`, Graph `Waypoints`, Settings `Settings`). Footer keeps the
account menu (email, theme, change password, sign out). Command palette (⌘K) lists the six pages
plus actions: "Create device token", "Export memories", "Change password".
A small `Badge` dot on Settings when a device needs attention (U9); on Activity when a job is
quarantined. No other badges.

Page header pattern (existing `PageHeader`): title (h1), one-line description, actions on the
right. Breadcrumb only on `/projects/[id]`.

## 2. Pages

### 2.1 Dashboard

- **Purpose:** show that Cairn makes agents better and cheaper, and flag anything that needs a person.
- **Question:** "Is Cairn working and is it worth it?"

```

│ │ ⚠ laptop-claude runs hook 0.1.4. Run `cairn update`.   [Devices]   │ │
│ │ ⚠ 1 job failed 5 times and stopped retrying.          [Activity]   │ │

│ │ ████████████▒▒░  stacked bar  │ │ Marked helpful           61      │ │
│ │ Active 351 · Stale 23 ·       │ │ Never used (durable)     97  [→] │ │
│ │ Superseded 31 · Expiring 7    │ │ Most used                         │ │

```

- **Components:** `Card`, `ChartContainer` + recharts `AreaChart`/`BarChart` (existing `chart.tsx`),
  `bar-list.tsx`, `Alert` (needs attention), `Tooltip` (method notes), `Select` (range 7/30/90 d),
  `Skeleton`, `Empty`, `Badge` (kind).
- **Stacked health bar:** one `div` row of segments with `role="img"` and an `aria-label` that reads
  every count; the legend below is plain text with counts (colour is never the only cue).
- **States:** loading = skeleton of the sentence + chart frame (fixed heights, no layout shift);
  error = `Alert` "Could not load stats. {server message}" + Retry; no usage yet (memories but zero
  lookups) = sentence becomes "No agent lookups yet. Savings appear after your agents search
  memory." and the chart shows the empty frame; first run = §3 checklist replaces everything
  above Memory health.
- **Interactions:** range select refetches `/stats?days=`; health segments and "Never used" link to
  `/memories` with the matching filter; most-used rows open the memory sheet; Needs-attention
  buttons deep-link (`/settings?tab=devices`, `/activity?tab=jobs`).
- **Copy:** the sentence is generated from numbers, never marketing ("~24,300 tokens of memory context",
  not "massive savings"). Tooltip on token figures: "Estimated: bytes ÷ 4." The benchmark card shows
  current values only, labelled "benchmark" (2,000 distractor memories, 43 questions), from the
  honest v2 run `bench/after-0.1.6-embed-v2.json` (hit@5 65%, the 0.1.6 final run). No older version appears anywhere in the web.

### 2.2 Memories

- **Purpose:** find any memory and see why it exists, what it replaced and whether it is used.
- **Question:** "What does Cairn know, and is this memory still true?"

```
┌ Memories ────────────────────────────────────────────── [Export] ┐
│ [Search title or summary…] [Project ▾] [Kind ▾] [Status ▾] [Branch ▾] │
│ 3 filters · Clear                                       412 results  │
│ Kind     Title                         Project   Status   Used  Updated│
│ gotcha   Migrations must be additive   cairn     Active   42    2 d   │
│ rule     Money is integer cents        billing   Stale ⓘ   3    9 d   │
│ …                                                  [Load more]       │
└──────────────────────────────────────────────────────────────────────┘
Sheet (?memory=id)                    
┌ gotcha · Active · project cairn · main ─────────────── [×] ┐
│ Migrations must be additive                                │
│ Summary … / Reason (why it was saved) …                    │
│ Symptom · Cause · Fix  (per-kind fields as a dl)           │
│ ── Why stale (only when stale) ─────────────────────────── │
│ src/billing/money.rs no longer exists on main (checked 2 d)│
│ ── Lineage ─────────────────────────────────────────────── │
│ Supersedes  rule  Money is float dollars      (superseded) │
│ Contradicts —                                              │
│ Related (auto) gotcha  cargo test failed until…            │
│ ── Evidence ────────────────────────────────────────────── │
│ src/db/migrate.rs · commit a1b2c3d · 3 captures           │
│ ── Usage ───────────────────────────────────────────────── │
│ Fetched 42 · helpful 9 · wrong 0 · last used 2 d ago       │
│ Saved by agent (laptop-claude) · created 2026-10-02        │
│ Expires —  (or "Expires in 12 days: handoff")              │
│                                      [Forget memory…]      │
└────────────────────────────────────────────────────────────┘
```

- **Components:** `data-table.tsx` (existing, server-paged via `x-next-cursor`), `InputGroup` search,
  `Select` ×4, `Badge` (kind, status), `Tooltip` (stale cause on the row icon), `Sheet`,
  `Separator`, `AlertDialog` (forget), `Skeleton`, `Empty`.
- **Status vocabulary (fixed):** Active, Stale, Superseded, Expired (=`expires_at` past, shown only
  when the filter asks for it), Forgotten is never listed. Each has a one-line tooltip:
  Stale = "Cairn doubts this: {cause}". Superseded = "Replaced by a newer memory".
- **Why stale copy:** `missing` → "{file or symbol} no longer exists on {default_branch} (checked
  {relative})". `feedback` → "An agent reported it as wrong {n} time(s)." Plus: "Stale memories
  that stay unused for 90 days expire on their own." No action button.
- **Lineage:** grouped by relation, both directions (`supersedes` / `superseded by`,
  `contradicts`, `causes`, `fixes`, `depends on`, `related`). Each row = kind badge, title, status;
  click swaps the sheet content (back button restores). Auto links carry a small "auto" badge.
- **States:** loading = 8 skeleton rows; empty (no memories at all) = `Empty` "No memories yet.
  Agents save memories as they work; finish setup in Settings › Devices." + link; empty (filters) =
  "No memories match these filters." + Clear filters; error = inline `Alert` above the table, filters
  stay usable; sheet 404 = "This memory was forgotten or expired." with Close.
- **Interactions:** typing debounced 250 ms; filters write the URL; Branch select is enabled only
  when one project is chosen (branches come from that project); row click or Enter opens the sheet;
  Esc closes; Forget = owner only (hidden otherwise), confirm copy from `lib/action-copy.ts`:
  "Forget '{title}'? Agents will no longer see it. This cannot be undone." → toast "Memory
  forgotten".
- **Copy:** column "Used" = fetched count; never show raw ids in the table (ids appear in the sheet
  footer with a copy button for support).

### 2.3 Activity

- **Purpose:** make Cairn's automatic work visible and keep an audit trail.
- **Question:** "What did Cairn and my agents do on their own?"

```
┌ Activity ──────────────────────────────────────────────────────────┐
│ [Timeline] [Audit log] [Jobs]                                      │
│ Today                                                              │
│  10:42  Cairn merged 2 duplicate memories into "Migrations must…"  │
│  10:41  Cairn linked 6 memories that cite src/billing/money.rs     │
│  09:15  Cairn marked 3 memories stale: files removed on main  [3▸] │
│  09:15  Cairn moved 4 memories from feat/refunds to main (merged)  │
│  08:02  Cairn wrote a handoff for feat/refunds (laptop-claude)     │
│ Yesterday                                                          │
│  23:00  Cairn expired 5 unused memories                            │
│  18:30  Cairn shared a gotcha with everyone (seen in 2 projects)   │
│                                         [Load older]               │
└────────────────────────────────────────────────────────────────────┘
Audit log: Time · Action · Subject · Device   (table, paged)
Jobs: Pending 2 · Running 1 · Stopped retrying 1
      Kind  Key  Attempts  Next retry  Last error (truncated, tooltip full)
```

- **Components:** `Tabs` (URL `?tab=`), plain `<ol>` list grouped by day with `<time>` elements,
  `Badge`, `data-table.tsx` (audit, jobs), `Tooltip`, `Button` (Load older), `Skeleton`, `Empty`.
- **Timeline event → sentence** (one map in `lib/action-copy.ts`; unknown actions render
  "Cairn: {action}" so nothing is hidden):

| Event | Sentence | Expand (`[n▸]`) shows |
|---|---|---|
| `memory_merged` | Cairn merged {n} duplicate memories into "{title}" | the merged titles |
| `links_added` | Cairn linked {n} memories that cite {entity} | linked titles |
| `memory_promoted` | Cairn shared a {kind} with everyone (seen in {n} projects) | source titles |
| `repo_state` | Cairn marked {stale} stale, revived {revived}, moved {promoted} from merged branches | memory titles per group |
| `memories_expired` | Cairn expired {n} memories ({by kind}) | titles |
| `session_distilled` | Cairn wrote a handoff for {branch} and saved {notes} notes ({device}) | handoff + notes |
| `job_quarantined` | A {kind} job stopped after {attempts} tries: {error} | — |

- **Audit log:** person/device actions only (`login`, `device_registered`, `project_renamed`,
  `memory_forgotten`, …), human labels ("Signed in", "Created device token 'laptop'").
- **Jobs (read-only):** non-admins see their own counts; admins see all rows. Quarantined rows
  read "Stopped retrying" with the error; copy under the table: "Cairn retries failed jobs
  automatically with backoff. A job that fails 5 times stops; it is retried again after the next
  server update." (see decision Q3 in §10).
- **States:** loading = 6 skeleton lines; empty timeline = "Nothing automatic yet. Cairn starts
  merging, linking and checking memories once your agents save some."; error per tab, other tabs
  still work; jobs empty = "No jobs waiting. Everything is processed."
- **Interactions:** expand rows inline (`button aria-expanded`); titles open the memory sheet;
  "Load older" pages with `before`; filter chips on Timeline: All · Merges · Links · Staleness ·
  Expiry · Handoffs (single-select, URL `?type=`).

- **Purpose:** explore how memories connect.
- **Question:** "What is related to what?"
- Keep the existing canvas and layout. Changes only: filters reuse the Memories URL params

### 2.6 Settings

- **Purpose:** the chores: connect agents, manage access, move data, account.
- **Question:** "How do I connect an agent / is my device OK?"

```
┌ Settings ──────────────────────────────────────────────────────────┐
│ [Devices] [Account] [Data] [Accounts (admin)]                      │
│ Devices                                         [Create device token]│
│ Name           Agent   Client  Last check-in   Status              │
│ laptop-claude  claude  0.1.6   3 min ago       ● Working           │
│ ci-codex       codex   0.1.4   2 d ago         ▲ Update needed     │
│ old-mac        —       —       41 d ago        ○ Not seen recently │
│                                         row menu: Rotate · Revoke  │
└────────────────────────────────────────────────────────────────────┘
Create dialog, step 1: Name [laptop-claude]  Agent (radio) ◉ Claude ○ Codex ○ OpenCode  [Create]
Create dialog, step 2:
│ 1. Copy your token (shown once)   ••••••••••••  [Show] [Copy token]   │
│ 2. Run on that machine:                                            │
│    cairn setup https://cairn.example.com --agent claude   [Copy]    │
│    Paste the token when it asks. It never goes in your shell history.│
│ 3. Start a new claude session. This dialog shows ✓ when it checks in.│
│    ◌ Waiting for first check-in…            [Done]                  │
```

- **Components:** `Tabs` (URL `?tab=`), `data-table.tsx`, `Dialog` (two-step create), `Field`,
  `Input`, radio group built from `Field` + native `<input type="radio">` (no new dependency),
  `InputGroup` + `Button` (copy), `Kbd`, `DropdownMenu` (row actions), `AlertDialog`
  (rotate/revoke), `Spinner`, `Badge`, `Tooltip`.
- **Device status rules** (computed by the server, §5): Working = hook check-in < 7 d and client is
  not older than the server; Update needed = client version older than the server's (any component), or a retired
  Python hook ("Run `cairn setup` again on that machine"); Not seen recently = no check-in for 7
  d; Never connected = token created, no check-in ("Run the setup command"). Status = icon + text,
  never colour alone. Tooltip shows the fix command with a copy button.
- **Create flow:** agent radio defaults to Claude; command updates live when the agent changes; the
  token is masked with Show/Copy (`aria-live` "Copied"); copy failure → "Could not copy. Select
  the text and copy it by hand." The dialog polls `GET /devices` every 3 s while open and visible
  (stop on close or after 10 min) and flips step 3 to "✓ Connected: claude 0.1.6". Closing before
  the check-in is allowed; the row shows "Never connected".
- **Rotate:** same step-2 panel with the new token; copy "The old token stops working now. Run the
  setup command again on that machine." Revoke: "Revoke '{name}'? Agents on that machine lose
  access immediately."
- **Account tab:** email (read-only), change password (existing dialog; min length from
  `MIN_PASSWORD`, show/hide toggle, `autocomplete="new-password"`), sign out of this browser.
- **Data tab:** Export: "Download all memories you can see as JSON." [Export] → file
  `cairn-export-YYYY-MM-DD.json`. Import: file input (`.json`), dry-run summary first ("212 new, 14
  already present, 3 invalid"), then [Import 212 memories]. Errors list line numbers. Both owner =
  the signed-in person; imported memories keep their scope only where the person may write it.
- **Accounts tab (admin):** register account, reset password (existing `accounts.tsx`), status.
- **States:** devices empty = first-run step 1 inline (same panel as §3); error = `Alert` + Retry.

## 3. First-run onboarding

Trigger: `stats.first_run` (§5) = no device has ever checked in **or** zero captures. Shown as a
`Card` at the top of the Dashboard; each step is a real control, not a description.

```
┌ Connect your first agent ──────────────────────────────── 1 of 3 done ┐
│ ✓ Signed in                                                           │
│ ① Create a device token          [Create device token]  (opens §2.6)  │
│ ② Run the setup command          cairn setup <url> --agent [claude▾]  │
│                                  [Copy]  Paste the token when asked.  │
│ ③ Start an agent session         ◌ Waiting for the first check-in…    │
│    then ◌ Waiting for the first capture…  → ✓ "First memories arrived: │
│    3 captures from laptop-claude, 1 note saved." [See memories]       │
└───────────────────────────────────────────────────────────────────────┘
```

Flow: login → Dashboard (checklist) → Create token dialog (same as Settings) → copy command → run
it → step 3 polls `/stats` every 5 s while the tab is visible (pause on `visibilitychange`, stop
after 15 min with "Still waiting. Run `cairn doctor` on that machine to see what is wrong.") →
check-in arrives (device row) → first capture arrives (`capture.last_at`) → success line with a
link to Memories; the checklist collapses into the normal dashboard on next load. Steps are an
ordered list (`<ol>`), each with a status announced via `aria-live="polite"`.

## 4. Copy guidelines (all pages)

- Sentence case everywhere; no all-caps labels, no eyebrows above headings, no "→" in buttons.
- Buttons say the action and keep it through the flow: "Create device token" → toast "Device token
  created"; "Forget memory" → "Memory forgotten"; "Export" → "Export ready".
- Cairn is the actor of automatic events; the person is "you"; agents by device name.
- Numbers: thousands separators, `tabular-nums`, `~` for estimates, relative time with absolute
  `title` tooltip, local timezone.
- Errors: what happened + what to do, no apology ("Could not reach the server. Check that it is
  running, then Retry."). Show the server `error` text when it is specific.
- Empty states always point at the next action (usually setup or `cairn init`).
- Never call memories "documents", "notes" (that is a kind) or "items". Kinds and statuses use the
  fixed vocabulary in §2.2.
- Code (commands, paths, branches) in `<code>`; every command shown has a copy button.

## 5. Data contract (what step 7a must provide)

`new` = new endpoint or field; everything else exists or is in W§1.

| Page | Request | Fields used |
|---|---|---|
| Dashboard | `GET /stats?tz=&days=7\|30\|90` | W§1.1 `Stats` **plus new:** `usage_days: {days: [{day, tokens, lookups, hits}], total_tokens, lookups, hit_ratio}`; `bench: {hit_at_5, search_tokens, get_tokens, session_tokens}` (current values only, constants compiled from the latest honest v2 bench file `bench/after-0.1.6-embed-v2.json`; no baseline or previous-version field exists); `memories.expired_30d`; `stale.by_cause {missing, feedback}` (rename of existing two fields); `usage.helpful_30d`; `devices_attention: [{device_id, name, reason}]`; `jobs.quarantined`; `first_run: bool`; `capture: {last_at?, observations_7d}` |
| Memories list | `GET /memories?limit&cursor&project&kind&status&branch&q` | **new params** `branch`, `q` (websearch over `search_tsv`, no usage counting), `status=expired`; rows **new fields** `project_name`, `fetched`, `stale_cause?` |
| Memory sheet | `GET /memories/{id}` (never counts usage) | `Record` **plus new:** `project_id`, `project_name`, `origin` (`agent`/`system`; today `#[serde(skip)]`), `stale_cause`, `checked_at`, `status_changed_at`, `created_at`, `expires_at`, `owner_is_me`, `device_name?`, `usage {fetched, helpful, wrong, last_used_at}`, `missing_entities: [string]` (file/symbol entities reported missing, for "Why stale"), `links[]` gains `other: {id, kind, title, status}` and `direction: "out"\|"in"` (incoming links included) |
| Activity timeline | `GET /auth/audit?actor=system&limit&before&type=` | **new param** `actor=system\|person`, `type`; **new system actions recorded** (one row per affected owner, `device_id` null): `memory_merged {into, merged:[ids], titles}`, `links_added {count, entity, ids}`, `memories_expired {count, by_kind}`, `session_distilled {handoff_id, branch, notes, device_id}`, `job_quarantined {kind, attempts, error}`; existing `memory_promoted`, `repo_state` gain `ids` per group. `AuditEvent` **new field** `titles: {id: title}` resolved server-side for visible ids only |
| Audit log | `GET /auth/audit?actor=person` | `AuditEvent` + **new** `device_name?` |
| Jobs | `GET /admin/jobs` (admin), `stats.jobs` (everyone) | `JobSnapshot` kind, key, status, attempts, not_before, last_error, updated_at. Step 7 **removes** the admin requeue/discard server routes, their audit actions (`job_requeued`, `job_discarded`) and the web buttons (U4) |
| Projects list | `GET /projects` | `ListedProject` **plus new:** `memories`, `stale`, `members`, `last_activity_at`, `default_branch` |
| Project branches | `GET /projects/{id}/branches` | `BranchSummary` **plus new** `handoff?: {id, title, summary, fields, updated_at, device_name?}` (latest visible handoff for that branch) |
| Project stale | `GET /memories?project=&status=stale` | as Memories |
| Project members | `GET /projects/{id}/members` | `Member` **plus new** `last_active_at?` (max of the member's session start / memory save in the project) |

Server-side capture of device health (new): the client sends `User-Agent: cairn/<version>
(<agent>; hook)` on hook calls and `(<agent>; mcp)` on MCP calls; on `/session/brief`,
`/observe` and `/session/end` the server stores `devices.client_version`, `devices.agent`,
`devices.last_hook_at` (throttled like `last_seen_at`). A `Python-urllib` agent string marks a
retired hook. Migration adds the three nullable columns.

constants exist.

Proxy allowlist additions: none beyond W§2.4 (`memories/export|import` sit under `memories`).

## 12. As built: step 7a (server)

Everything in §5 exists on the server; the web does not use it yet (7c wires it). Where the build
differs from the text above:

- **`GET /stats?tz=&days=`** (web session). `tz` -840..840 and `days` 7, 30 or 90, else 400. Fields:
  `memories {total, by_kind, by_status, by_scope, by_origin, expired_30d}`, `activity [{day, saved}]`
  (`days` local days, zero-filled), `usage {never_fetched, fetched_30d, helpful_30d, top[≤5]}`,
  `usage_days {days [{day, tokens, lookups, hits}], total_tokens, lookups, hit_ratio}`,
  `bench {hit_at_5, search_tokens, get_tokens, session_tokens}` (constants equal to
  `bench/after-0.1.6-embed-v2.json`, the latest v2 run; a unit test keeps them in step),
  `stale {total, by_cause {missing, feedback}, expiring_30d}`, `links {total, auto,
  durable_with_link_ratio}`, `memory_health {expiring, stale_missing, stale_feedback, linked_ratio}` (the
  dashboard card, same numbers), `jobs {pending, running, quarantined}` (admin: all jobs), `projects`,
  `devices_checked_in`, `devices_attention [{device_id, name, reason}]` (update needed only), `first_run`,
  `capture {last_at, observations_7d}`. There is no baseline or comparison field.
- **Usage capture** (`retrieval_log`, 15-minute buckets, kept 120 days): `/search`, `/get`, `/session/brief` and
  `/session/topic` each count one lookup; `hit` means the reply held something; tokens are response bytes / 4.
  `helpful_30d` counts helpful votes in the last 30 days (`usage_votes.created_at`).
- **Memory view.** `GET /memories`, `GET /memories/{id}` and `GET /projects/{id}/memories` return the console
  shape (`MemoryView`): the memory plus `origin`, `project_name`, `owner_is_me`, `device_name` (owner only; the
  device that saved it, `memories.device_id`), `checked_at`, `status_changed_at`, `fetched`, `usage`,
  `missing_entities` and `links[]` with `direction` and `other {id, kind, title, status}`. `/get` (agents) is
  unchanged and never shows these. Params: `status=expired|active|stale|superseded`, `branch`, `q` (websearch over
  `search_tsv`), plus the existing ones. Nothing here counts a fetch.
- **Audit.** `GET /auth/audit?limit=&before=&before_id=&actor=system|person&type=a,b`. The next page passes the last
  row's `created_at` as `before` and its `audit_id` as `before_id` (rows within one second would be lost with
  `before` alone). Each event may carry `device_name` and `titles {id: title}`, resolved at read time for the
  memories the reader can still see (so a forgotten memory's title never lingers in metadata). New system actions,
  one row per owner: `memory_merged {into, merged}`, `links_added {count, entity, ids}`, `memories_expired {count,
  by_kind, ids}`, `session_distilled {handoff_id, branch, notes, device_id, ids}`, `job_quarantined {kind, attempts,
  error}`; `memory_promoted` and `repo_state` gained `ids`. `memory_withdrawn` (already recorded) belongs to the
  system set. Person actions now recorded: `login`, `logout`, `password_changed`, `account_registered`,
  `project_initialized`, `memory_forgotten`.
- **Projects.** `GET /projects` rows gain `memories` (live), `stale`, `members`, `last_activity_at`;
  `GET /projects/{id}/branches` rows gain `handoff` (the reader's latest handoff on that branch) and also list a
  branch that only has a handoff; members gain `last_active_at`.
- **Devices.** `GET /devices` rows gain `agent`, `client_version`, `last_hook_at`, `health`, `health_reason`,
  `fix_command` (revoked devices: null). Clients send `User-Agent: cairn/<version> (<agent>; hook|mcp|cli)`; the
  server records it on any device-token request (the hook check-in at most once a minute). `Python-urllib` marks
  the retired hook.
- **Health.** `GET /health` gains `version` and `public_url` (`CAIRN_PUBLIC_URL`, else `x-forwarded-proto` and
  `x-forwarded-host` or `host`).
- **Export and import** (web session only). `GET /memories/export` downloads `cairn-export-YYYY-MM-DD.json`
  (`{version: 1, exported_at, memories[]}`, the person's own live memories, handoffs excluded).
  `POST /memories/import[?dry_run=1]` takes that file and answers `{new, duplicate, invalid [{index, error}]}`; a
  project memory is accepted only for a project the person already belongs to (import never joins a project).
- **Auth.** `session_required` for a missing, unknown, expired or revoked session and for a device token on a
  console route; `invalid_credentials` for a failed sign-in or a wrong current password; `unauthorized` for a bad
  device token. The texts did not change. `Session.expires_at` is a number. No limiter, no lockout; login verifies a
  dummy Argon2 hash for an unknown email.
- **Removed.** `POST /admin/jobs/{id}/requeue` and `/discard`. Quarantined jobs retry once at the first start of a
  new server version and after 24 hours.
- **Removed in 7c** with the web's last use: `POST /delete` (the web calls `POST /forget`, the same erase),
  `GET /diagnose` (the web reads `GET /stats`) and `POST /export` (the web downloads `GET /memories/export`).

## 13. As built: step 7b (generated types)

The web reads its wire types from `apps/web/lib/generated/*.ts` (ts-rs 11, feature `ts`; `lib/types.ts` keeps
only `Diagnostics`, which goes with `GET /diagnose` in 7c). No UI behaviour changed; the wire JSON is unchanged.

- **Generate:** `cargo test --workspace --features ts export_bindings` (from any directory; `.cargo/config.toml` sets
  `TS_RS_EXPORT_DIR`). The spec's `-p cairn-server` form writes only the types the server's own structs reach, so
  the workspace form is the one to use. Output is deterministic (no timestamps; run twice, no diff). CI
  (`rust-tests`) deletes the directory, regenerates, and fails on `git diff` (`add -N` so new files count).
- **Exported types** (file = type name): core `Kind Scope Status Relation EntityKind Context Memory Record Entity
  Link Fields` (+ per-kind `Decision Rule Gotcha Procedure Fact Preference Note Handoff`), `Origin Project Account
  AccountStatus Device DeviceStatus DeviceHealth AuditEvent Graph Node Edge Card Cards`; store `Job JobSnapshot
  Stats` (+ `Bench Counts Day UsedMemory UsageReport UsageDay UsageDays StaleCauses StaleReport LinkReport
  MemoryHealth JobCounts DeviceAttention Capture`), `MemoryView UsageView LinkView LinkOther BranchSummary
  BranchHandoff Conflict ImportReport Invalid DeviceRegistration`; server `Health Session DeviceView ErrorBody
  ErrorCode`, and the route structs renamed for the web: `Listed` is `ProjectView`, `MemberRow` is
  `ProjectMember`. `serde_json/JsonValue.ts` comes with `BranchHandoff.fields`.
- **Numbers:** ts-rs maps `i64` to `bigint`, and 11.1 has no global switch, so every `i64` field (and the
  `BTreeMap<String, i64>` of `Counts`) carries `ts(type = "number")`; all values are < 2^53. `u32`, `usize`, `f32`
  and `f64` are already `number`.
- **Optional keys:** `skip_serializing_if` is typed as an optional key only when `serde(default)` sits beside it, so
  the per-kind field structs, `Memory`, `Record`, `Card`, `Cards` and `AuditEvent` carry both (serde ignores
  `default` when serializing). `Fields` is the union of the per-kind objects; narrow by `memory.kind`.
- **Error codes:** `ApiError.code` is now the `ErrorCode` enum (snake_case, the same nine strings as before) and the
  body is `ErrorBody { error, code }`; 7c switches the web on `code` instead of message text.
- **Overrides** that keep a type honest: `AuditEvent.metadata` is `Record<string, unknown> | null` (an object bag,
  not any JSON), `LinkView.direction` is `"out" | "in"`, project `role` is `"owner" | "member"`.
- **Replaced by generated types:** the hand-written `ListedProject`, `ProjectBranch`, `Account(Row)`,
  `QuarantinedJob`/`JobQueue`, `MemoryLink`, `ProjectMemory` and its `...Extras` shims, `MemoryGraph*`,
  `ProjectMember`, `Device`, `DeviceRegistration`, `AuditEvent`, `BranchHandoff`. Still hand-written for 7c:
  `DashboardStats`, `UsageDays` (dashboard `loadStats` joins old endpoints), `Diagnostics`.
- **For 7c wiring:** import `Stats`, `ImportReport`, `ErrorCode`, `ErrorBody`, `Session` from `@/lib/generated/*`;
  `Session.expires_at` is a number. `AuditEvent` has no `before_id` param type (query params are not generated).
