# 0.1.6 Step 6 — Processing (deterministic, no LLM)

Base: steps 3–5 done. Depends on: C§1 and C§2.1 (typed captures `kind`/`ok`, `files`,
`commands`), C§2.2/C§2.3 (`/session/brief`, `/session/topic`), C§5 (hook state), R§0 R1
(`memories.embedding`), R§4.6 (brief), R§3.3 (entity channel uses `entities::derive`),
S§2 (`memory_save` description already says what quality needs), F§2.3 (kind policy, forget),
F§7.2 (consolidation bands). Hands off to step 7 (stats read `origin`, `stale_cause`, links).

## 0. Decisions

| # | Decision | Why |
|---|---|---|
| P1 | Entity extraction adds `module` (parent directory) and stricter symbol/command/test rules; one function serves save, link jobs and the search entity channel. | Graph and entity channel need shared, normalised names. |
| P2 | A new job kind `link` (enqueued on every save/update) writes auto links from shared entities and gotcha fix/cause entities. Cosine bands stay in `consolidate`. | Links must not depend on the embedding model being loaded. |
| P3 | Auto links stay inside a **cohort**: same `project_id` (non-null), or same owner; the one exception is a global promotion copy, which links to its sources (§4.3). | A link must never expose a memory to someone who cannot see it. |
| P4 | Save quality checks for agent saves return one-line `400 quality` errors. System saves are built to pass them. | Automation first: the agent fixes its own save. |
| P5 | Staleness from git: the brief reply asks the hook to check up to 200 cited files and 20 symbols on the default branch; the hook reports missing/present and merged branches to `POST /session/repo-state`. | The server cannot read repositories; the hook already runs git. |
| P6 | Merge promotion: on the default branch, memories whose `repo_branch` is in the hook's `git branch --merged` list move to the default branch; their handoffs expire. | Replaces the deleted manual "record merge" (A14). |
| P7 | One handoff per (owner, project-or-repo, branch, worktree), replaced on each distill. | F§2.3 had one per session; owner asked one per checkout. |
| P8 | Distillation rules: labelled lines (kept), fail→fix gotcha, passing test command fact, handoff from edits/failures/markers. Nothing titled `Session <id>`; system notes are `personal`. | P§2.1. |
| P9 | Global promotion: a project rule/gotcha whose near-identical twin (cosine ≥ 0.92) exists in another project of **any owner** produces one global copy linked to both sources. Guards: only `scope = project` memories of kind rule/gotcha are promoted and a personal memory never is; the copy is re-redacted; it is withdrawn when fewer than 2 live sources remain. | Deterministic. The same lesson learned twice, in two projects, is shared with everyone; the guards keep personal text out, keep secrets out, and drop the copy when its evidence disappears. |
| P10 | Expiry by kind and origin; **system-derived** stale memories unused for 90 days expire (an agent's memory never does; stale only lowers its rank); observations are purged 7 days after their session is distilled. | Bounded storage without human cleanup. |
| P11 | Human review queue: confirmed gone (table, routes, web) — step 6 adds a CI grep guard only. | F§D8 already replaced it. |

## 2. Migration `migrations/0004_processing.sql`

```sql
ALTER TABLE memories
    ADD COLUMN origin            text NOT NULL DEFAULT 'agent' CHECK (origin IN ('agent','system')),
    ADD COLUMN stale_cause       text CHECK (stale_cause IN ('feedback','missing')),
    ADD COLUMN status_changed_at timestamptz NOT NULL DEFAULT now(),
    ADD COLUMN checked_at        timestamptz;                      -- last git check
ALTER TABLE entities DROP CONSTRAINT entities_kind_check;
ALTER TABLE entities ADD CONSTRAINT entities_kind_check
    CHECK (kind IN ('file','module','symbol','command','test','service','term'));
ALTER TABLE jobs DROP CONSTRAINT jobs_kind_check;
ALTER TABLE jobs ADD CONSTRAINT jobs_kind_check CHECK (kind IN ('embed','distill','consolidate','link'));
CREATE INDEX memories_stale_idx ON memories (status_changed_at) WHERE status = 'stale';
```

(Constraint names: confirm with `\d entities` / `\d jobs`; the foundation DDL uses inline checks,
so Postgres names them `<table>_kind_check`.) Every status write sets `status_changed_at = now()`;
the feedback path sets `stale_cause = 'feedback'`. `Memory` gains `origin: Origin`
(`#[serde(skip)]`), `stale_cause: Option<String>` (`skip_serializing_if none`).

## 3. Entity extraction (`crates/core/src/process/entities.rs`)

`derive(texts, context) -> Vec<Entity>` keeps its signature and the cap of 32. Order of
extraction (first wins on the cap): context lists, then backticked spans, then bare text.

| Kind | Source | Normalisation |
|---|---|---|
| file | `context.files`; `looks_like_path` words (existing rule); backticked paths | trim, `\`→`/`, strip `./`, strip a leading `context.worktree + "/"`, no trailing `/` |
| module | parent dir of every file entity | skip empty and the single segments `src`, `lib`, `app`, `crates`, `packages` |
| symbol | `context.symbols`; backticked or bare tokens matching `^[A-Za-z_][A-Za-z0-9_]*(::[A-Za-z_][A-Za-z0-9_]*)+$`, `^[a-z][a-z0-9]*([A-Z][a-z0-9]*)+$` (camelCase), `^[A-Z][a-z0-9]+([A-Z][a-z0-9]*)+$` (PascalCase, ≥ 2 humps), `^[a-z][a-z0-9]*(_[a-z0-9]+)+$` (snake_case, ≥ 2 parts, not all digits) | strip trailing `()`, `!`, `;`; keep case |
| test | `context.tests`; symbols starting `test_` or ending `_test`/`Test`; files under `tests/` or matching `*_test.*`, `*.test.*`, `test_*.py` (the file entity is also kept) | as symbol/file |
| command | `context.commands`; backticked spans with whitespace whose first word is in `cargo npm pnpm yarn npx node git docker kubectl make python python3 pytest go psql cairn bash sh just uv` | collapse spaces; cut at the first `|`, `&&`, `;`, `>`; keep the first 3 words |
| service | `context.services` | trim, lower-case |
| term | backticked single lower-case words not matched above | lower-case |

Bare-text symbol matching skips words inside URLs and words of ≤ 3 chars. Tests in `entities.rs`
pin one positive and one negative case per row.

## 4. Auto links

### 4.1 `link` job (`crates/store/src/link.rs`, new; `worker.rs` claims `JobKind::Link`)

Enqueued with key = memory id by `save`, distill writes and any change of title/summary/fields.
Body:

```
m = memory(id); if m.status not in (active) or m.kind == handoff: done
cohort(o) := (m.project_id is some and o.project_id == m.project_id) or o.owner_id == m.owner_id
-- R1 shared entities
cands = SELECT e2.memory_id,
          sum(CASE WHEN e2.kind IN ('file','symbol','test') THEN 2 WHEN e2.kind = 'module' THEN 1 ELSE 0 END) AS score
          FROM entities e1 JOIN entities e2 ON e2.name = e1.name AND e2.kind = e1.kind AND e2.memory_id <> e1.memory_id
          JOIN memories o ON o.memory_id = e2.memory_id
         WHERE e1.memory_id = $m AND e1.kind IN ('file','module','symbol','test')
           AND o.status = 'active' AND o.kind <> 'handoff' AND {cohort(o)}
         GROUP BY e2.memory_id ORDER BY score DESC, e2.memory_id LIMIT 5
for (o, score) in cands where score >= 1: insert_link(m, o, relates, auto)
-- R2 gotcha fix/cause
if m.kind == gotcha:
    names = derive([fields.fix, fields.cause], {}).filter(kind in file/symbol/command/test)
    for o in cohort memories of kind decision|rule|procedure having an entity in names (≤ 3, by match count):
        insert_link(source = o, target = m, fixes, auto)
if m.kind in (decision, rule, procedure):
    for g in cohort gotchas (≤ 500, newest) whose derive([fix, cause]) intersects m's entities (≤ 3):
        insert_link(source = m, target = g, fixes, auto)
```

`insert_link` skips when any link already exists between the pair in either direction, or when
the pair already has 8 auto links on either side (`count(*) WHERE origin = 'auto'`). Insert
`ON CONFLICT DO NOTHING`. Agent links are never removed by the job.

### 4.2 Consolidate tuning (`crates/core/src/process/consolidate.rs`, `crates/store/src/consolidate.rs`)

Unchanged bands (F§7.2): same owner, kind, scope, project; cosine ≥ 0.92 newer supersedes older,
0.75–0.92 `relates`. Added guards: no auto-supersede when both `repo_branch` are set and differ
(branch-specific knowledge); no auto-supersede of an `origin = 'agent'` memory by an
`origin = 'system'` one (it gets `relates` instead). Tie-break for "newer": `created_us`, then id.

### 4.3 Global promotion (end of the consolidate job)

Across all owners and projects, with these guards: (1) only a `scope = project` memory of kind rule or
gotcha, origin agent, status active is a candidate, and so is its twin; personal memories (and every other
kind) are never read as twins and never promoted; (2) the copy is built by `save_as(.., Origin::System)`,
which runs the same redaction as every save (`redact_sensitive_content` over title, summary, reason, fields
and evidence), so a secret that slipped into a project memory is not republished; `context` is empty (no
repo, branch, worktree, commit); (3) the copy is linked to its sources; (4) it is withdrawn when fewer than 2
live sources remain.

```
if m.scope == project and m.kind in (rule, gotcha) and m.origin == agent and m.status == active:
   twins = SELECT o FROM memories o WHERE o.scope = 'project' AND o.project_id <> m.project_id
             AND o.kind = m.kind AND o.status = 'active' AND o.origin = 'agent'
             AND o.embedding IS NOT NULL ORDER BY o.embedding <=> m.embedding LIMIT 5      -- any owner
   twin = first with cosine >= 0.92;  if none: done
   g = SELECT global memory, origin system, same kind, with cosine(m) >= 0.92        -- any owner
   if g is none:
       g = save_as(owner = 'system', SaveInput{kind, title, summary, reason, fields from the newer of (m, twin),
                   evidence = none, scope: global}, context {}, Origin::System)         // redacted again
   insert_link(g, m, relates, auto); insert_link(g, twin, relates, auto)   // agent cap ignored for g
```

The global copy is owned by the reserved `system` account (created on first use, disabled, hidden from the
account list) and carries no evidence: it holds the newer source's lesson text and links to its sources, so
neither a person's authorship nor a project's paths, commits or URLs are published. Everyone can read it and
nobody can forget it; it is withdrawn when its sources go. A link from `g` to a source shows only to readers who can read the source (`attach` rule), so
promotion exposes no project's memory list. The identity unique index makes a repeat a no-op.

Withdrawal: a source is *live* when it is linked from `g` by `relates`/`auto`, scope project, status active or
stale, not expired, not forgotten. At the end of the consolidate job and in the sweep tick, every promoted
global (`origin = system`, scope global, kind rule/gotcha, with source links) that has fewer than 2 live
sources gets `expires_at = now()`, which hides it from every read. If two live sources return (an identical
re-promotion or a source revived), the identity save clears `expires_at` and the copy is live again. Audit
`memory_promoted {global_id, sources}` and `memory_withdrawn {global_id, live}`.

## 5. Save quality (`crates/core/src/memory/validate.rs`)

`validate_quality(input: &SaveInput, fields: &Fields) -> Result<(), Error>`, called from
`process::prepare_save` when `origin == Origin::Agent`, after `validate_save`. First failing rule
wins; error = `Error::Quality(String)` → HTTP 400 `{code: "quality", error: <message>}`.

| Rule | Message (exact) |
|---|---|
| title chars 8..=80 after trim | `title: use 8-80 characters that name the knowledge` |
| summary chars 20..=240 after trim | `summary: use 20-240 characters saying what is true` |
| summary ≠ title (trimmed, case-insensitive) and summary does not equal title + punctuation | `summary: repeats the title; say what is true in 1-3 sentences` |
| kind ≠ note → reason ≥ 10 chars | `reason: say why this is true or was chosen (10+ characters)` |
| gotcha → `fields.fix` non-empty | `fields.fix: say how the gotcha was fixed` |
| procedure → `fields.steps` ≥ 2 | `fields.steps: list at least 2 ordered steps` |
| preference with scope project/global | existing error, unchanged |

Server-chosen scope (F§2.3, built in step 2) is unchanged and now documented in
`docs/contracts/mcp-layer1.md`: omitted scope → preference/note `personal`; other kinds `project`
when the request context names a project the person belongs to, else `personal`; `global` only
when the agent asks. All 70 bench corpus memories pass these rules (checked while writing this
spec).

### 6b as-built (entities, links, quality, consolidate, promotion)

Built: migration `0004_processing.sql` (all §2 columns; `status_changed_at` is set on every status write and
`stale_cause = 'feedback'` on the feedback path; `Memory.origin`/`stale_cause`), §3 entities, the `link` job
(`store/src/link.rs`, claimed by `worker.rs`), §5 quality (`Error::Quality`/`StoreError::Quality` → 400 `quality`),
§4.2 guards (`process::consolidate::guard`) and §4.3 promotion/withdrawal (`store/src/consolidate.rs`). Tests:
`store/tests/processing.rs` (10), core `entities_rows`, `module_skips_top_level_src`, `quality_messages`,
`consolidate_keeps_branch_specific`, `agent_saves_are_quality_checked_and_system_saves_are_not`, server
`quality_error_is_400_quality_one_line`. Not in 6b (6c): `system_outputs_pass_quality`, distill tests, handoff id.

Deviations from the text above:

- **R2 runs before R1** in the link job, so a gotcha and the procedure/rule that cites its fix get `fixes`, not
  `relates` (their shared entity would otherwise always win and `fixes` would never be written).
- **Cohort adds** `o.scope <> 'personal' OR o.owner = m.owner` and excludes promoted global copies: a personal
  memory kept inside a project (system notes keep `project_id`) must not link to another member's personal memory,
  and a promoted copy's links are only its sources. The link job also skips a promoted copy as subject.
- **Modules are appended last** (after the context lists, backticked and bare entities), so they are first to go
  at the 32 cap. `rustc`/`tsc` are not command programs (spec list of 20 kept).
- **Promotion**: an existing copy is found first through a link to either source (it may not be embedded yet),
  then by cosine. Promotion and withdrawal take one advisory lock so two twins promoting at once make one copy.
  Withdrawal covers every `origin = system`, global rule/gotcha with fewer than 2 live sources, including one
  whose sources were all forgotten (forget deletes the links, so "with source links" would never match). Revival
  is done by the same reconcile pass (`expires_at <= now()` and two live sources again), not only by an identity
  save. 6c: a system gotcha gets a 180-day expiry (§10); reconcile would revive a copy expired that way if two
  live sources exist, so 6c should either skip promoted copies there or keep the 180 d reset on read.
- **Quarantine auto-retry** (owner decision, not in this spec): the sweep puts a job quarantined for an hour back
  to pending with one attempt left (`Store::retry_quarantined`), so a poison job costs one try an hour and a fixed
  one heals. The admin requeue/discard routes and the web buttons still exist; step 7 should drop them.
- **Quality fallout**: `bench_distractors.py` one-sentence rules got a second sentence in the summary (the
  summary equalled the title); `smoke_mcp.sh`/`smoke_web.sh` summaries lengthened. Tests with thin saves were
  lengthened; `store::testing::rule` pads a title under 8 characters.
- A save now leaves two pending jobs (embed, link); job-count tests were updated.
- Bench: `links.durable_with_link_ratio` over the 62 fixture durable memories (any relation, via SQL after jobs
  drain), `links.all_memories` with distractors, and `--min-link-ratio` (CI v1 gate 0.60).

### 6c as-built (git staleness, merge promotion, handoff identity, distill rules, expiry, topic cards)

Built per §7–§11: `store/src/repo.rs` (`Store::brief_check`, `Store::repo_state`, `POST /session/repo-state`, device

additions and the expiry extension on fetch and helpful vote, topic cards (`Store::topic`, `topic_card`, hook injects
`card`), the bench session additions and the CI review guard. Tests: core `distill_*` (6), `handoff_id_per_checkout`,
`system_outputs_pass_quality`, `expiry_follows_kind_and_origin`, `topic_card_is_one_bounded_line`,
`handoffs_match_their_checkout`; `store/tests/staleness.rs` (`repo_state_marks_stale_and_revives`,
`repo_state_rejects_non_default_branch`, `brief_check_*`, `merge_promotes_branch_and_expires_handoff`,
`distill_writes_system_gotcha_fact_and_one_handoff_per_checkout`,
`sweep_expires_unused_stale_and_purges_distilled_observations`, `fetch_extends_system_expiry_but_not_a_promoted_copy`,
`topic_gives_notes_for_one_or_two_and_a_card_for_three`, `observations_keep_their_capture_order_within_one_second`);
client `session_start_reports_repo_state`, `a_topic_card_is_injected_as_one_bounded_line`.

Deviations from the text above:

- **Promoted copies are not aged** (6b note): `expires_at(kind, system, scope, now)` gives the 180 days only to
  `origin = system` gotchas/facts whose scope is not `global`, and `mark_fetched`/helpful vote skip global copies, so the
  sweep never expires a copy that reconcile would then revive. Withdrawal (`expires_at = now()`) is unchanged.
- **Typed-note quality**: a D1 note's summary was its title (`summary repeats the title`, so no typed note could pass
  §5). The summary is now `<kind> noted in a session: <line>`, a Reason under 10 characters falls back to the default
  reason, and `distill` drops any note that still fails `validate_quality` (a gotcha with no fix, a one-step
  procedure, a title under 8 characters). `system_outputs_pass_quality` asserts it.
- **D4 markers read prompts only** (both next steps and open questions); assistant text is never a handoff line.
- **Observation order**: captures are stored with `clock_timestamp()` instead of the request's second-resolution
  `captured_at`, so a fast failure, edit, pass sequence keeps its order (event ids are hashes and do not sort by
  time). `Observation.captured_at` read back is still whole seconds.
- **Files are found with `git ls-files --cached --others --exclude-standard`** (not `git ls-files` alone) so a file
  the agent just created is not reported missing; the hook never touches the file system for a name the server sent.
- **Check ordering** is "never checked first, then oldest check, then name" (`bool_or(checked_at IS NULL) DESC,
  min(checked_at), name`); a bare `min(...) NULLS FIRST` ignores NULLs inside a group.
- **Filter**: `Filter.session_id` no longer pins a handoff to one session (the id is per checkout now); a handoff

## 7. Staleness and merge promotion from git

### 7.1 Brief reply gains `check` (`routes/retrieve.rs`, `store/retrieve.rs::brief`)

`{brief, check?: {project_id, branch, files: [String] (≤ 200), symbols: [String] (≤ 20)}}`. Present
only when `ctx.project_id` is a project the person belongs to and `ctx.branch` equals
`projects.default_branch` (NULL → `main` or `master`). Files/symbols = distinct `file`/`symbol`
entities of the project's `active` memories and `stale` memories with `stale_cause = 'missing'`,
ordered by `min(memories.checked_at) NULLS FIRST`, then name.

### 7.2 Hook (step-4 `hook/mod.rs` SessionStart, after printing the brief)

```
if reply.check:
   tracked  = set(`git ls-files -z`)                                  // one process
   missing  = [f for f in check.files if f not in tracked]; present = the rest
   found    = set(`git grep -h -o -w -F -e s1 … -e s20`) (timeout 1.5 s; on timeout: symbols skipped)
   merged   = `git branch --merged HEAD --format=%(refname:short)` minus the current branch (≤ 50)
   POST /session/repo-state {project_id, branch, commit, files_missing: missing, files_present: present,
        symbols_missing, symbols_present, merged_branches: merged}   // 2 s timeout, no outbox
```

### 7.3 `POST /session/repo-state` (device token; `routes/capture.rs`, `store/src/repo.rs` new)

Reject (400) when the person is not a member or `branch` is not the default branch. In one
transaction:

```
for m in project memories citing a reported name (scope project, status active, or stale with stale_cause='missing',
  repo_branch NULL or the default branch):
   F = m.file entities that are repo-relative (no leading / or ~, no `..`, no `:`);  S = m.symbol entities
   checked = (F ∩ (files_missing ∪ files_present)) ∪ (S ∩ (symbols_missing ∪ symbols_present))
   if checked empty: continue
   gone = F nonempty and F ⊆ files_missing and (S empty or S ⊆ symbols_missing)   -- symbols alone never decide
   back = F ∩ files_present nonempty or S ∩ symbols_present nonempty
   if m.status == active and gone: status = stale, stale_cause = 'missing'
   if m.status == stale and m.stale_cause == 'missing' and back: status = active, stale_cause = NULL
   checked_at = now()
merge promotion (this order):
   UPDATE memories SET expires_at = now() WHERE kind = 'handoff' AND project_id = $p AND repo_branch = ANY($merged) AND owner_id = $person
   UPDATE memories SET repo_branch = <branch> WHERE project_id = $p AND kind <> 'handoff' AND repo_branch = ANY($merged) AND owner_id = $person
audit repo_state {stale, revived, promoted}
reply {stale: n, revived: n, promoted: n}
```

## 9. Distillation rules (`distill(observations) -> Distilled`, pure)

Input: one session's observations in `captured_at, event_id` order (step-4 `kind`, `ok`,
`context.files`, `context.commands`).

- **D1 labelled lines** — existing `typed_notes` over `prompt` and `assistant` observations only.
- **D2 fail → fix gotcha** — `key(cmd)` = first two words of the normalised command (§3 command
  rule). For each failed command F (`ok == Some(false)`): the first later command S with the same
  key and `ok == Some(true)`, with ≥ 1 `edit` observation between them. Emit (≤ 3 per session, one
  per key):
  - title `` `{key}` failed until {f1}[, {f2}] changed `` (basenames of the first two edited files; clip 80)
  - summary = F's error line (content after `exit <n>: `) if ≥ 20 chars, else
    `` `{key}` failed, then passed after editing {files ≤ 3}. `` (clip 240)
  - reason `Seen in one session: the command failed, files were edited, then it passed.`
  - fields `{symptom: error line or "`{key}` exited non-zero", fix: "Edited " + files (≤ 5)}` — no cause (not invented)
  - evidence = event ids of F, the edits, S; context.files = edited files.
- **D3 test command fact** — first successful command whose normalised form starts with one of
  `cargo test`, `cargo nextest`, `npm test`, `npm run test`, `pnpm test`, `yarn test`, `pytest`,
  `python -m pytest`, `go test`, `make test`, `just test`: title `` Tests run with `{cmd ≤ 50}` ``,
  summary `` `{cmd}` is the test command that passed in this repository. ``, reason
  `Observed a passing run in a session.`, fields `{source: "session capture"}`. Identity makes
  repeats a dedupe.
- **D4 handoff** — `next_steps` = existing marker lines from `prompt` observations; `open_questions`
  = existing markers plus `` `{key}` still failing: {error line} `` for failed keys with no later
  success; `files` = edited files (≤ 20). Emit when edits > 0 or either list is non-empty. Title
  `Handoff: {branch or repository basename or "workspace"}`; summary
  `{n} files edited; {k} open items; last activity {YYYY-MM-DD}.`; reason
  `Derived from the captures of one session.`
- All outputs: `Origin::System`, scope `personal` (project_id kept), must pass §5 (test asserts).
  The old `Handoff {session_id}` title is deleted.

```sql

 WHERE m.origin = 'system' AND m.status = 'stale' AND m.status_changed_at < now() - interval '90 days' AND m.expires_at IS NULL
```

## 17. Review fixes (step 6 review)

Applied after the review of commits cc8dd55, 78e2742, 9b98676:

- **Stale never deletes agent memory.** The 90-day stale expiry applies to `origin = system` rows only.
  "Missing" is decided only by repo-relative files on memories made on the default branch (or none): absolute,
  `~`, `..` and `x:` names, symbols alone, and branch-only memories never go stale. The hook leaves out a name
  that is gitignored, exists on disk, or is the tail of a tracked path (a monorepo subdirectory name).
- **Promotion privacy.** The copy has owner `system` and no evidence (§4.3).
- **repo-state** changes only the reporter's own handoffs and branches (project memories go stale from any
  member's default-branch report) and locks only the memories that cite a reported name.
- **Jobs.** The quarantine retry revives only the newest row per key; `sweep` runs reconcile even when the
  retry fails.
- **Twin search** uses the retrieval shape (materialised CTE ordered by a bound vector, iterative scan on).
  The promotion lock is per kind and taken only after a twin is found; reconcile runs after a promotion or
  supersede and in the sweep. Reconcile revives only an `active` copy, so a copy flagged wrong lapses with
  the stale rule instead of flapping.
- **Handoffs.** Forgetting a handoff forgets that content; the next different handoff replaces the row.
- Not changed (accepted): link cap applied after `LIMIT 5`, personal-to-project links counting toward the
  cap, multi-replica link duplicates, a withdrawn copy being hard-deleted 30 days after withdrawal (a later
  twin then makes a new copy), `GOTCHA_SCAN = 500`, 8-character title minimum for short CJK titles.
