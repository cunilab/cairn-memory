# 0.1.6 Step 5 — Retrieval

Base: steps 3 and 4 done. Depends on: S§3.1 (`/search` request with `kind`, `limit`, `budget`;
`Cards` reply), S§3.2 (`/get` counts usage), C§2.2 (`/session/brief` receives `recent_files`;
1,200 B cap), C§2.3 (`/session/topic` never counts usage), F§1.2 schema (`memories`, `entities`,
`links`, `usage`, `memory_embeddings`), F§2.3 kind policy. Hands off to step 6 (entity/link
quality feeds the entity and neighbour channels; `stale` status is ranked here).

## 0. Decisions

| # | Decision | Why |
|---|---|---|
| R1 | The embedding moves onto `memories` (`embedding vector(384)`, `embedding_model`, `embedding_source`), with a partial HNSW index. `memory_embeddings` is dropped. The vector channel runs pgvector **iterative index scan** (`hnsw.iterative_scan = relaxed_order`) with the full visibility predicate in the same `WHERE`. | Visibility inside the scan needs the filter columns on the indexed table. Rejected: post-filtering a global top-K (a person with 2 % of rows gets < K hits — the step-2 behaviour, F§6 2c as-built); partitioning (visibility = own ∪ projects ∪ global per person, not a partition key); denormalised copies on `memory_embeddings` (trigger sync for status, expiry and membership). |
| R2 | Lexical channel: `websearch_to_tsquery('english', q)` with `&` turned into `|` unless the query has a negation. Each candidate also gets a **coverage** = matched query lexemes / query lexemes. | AND semantics drop partial matches; OR without coverage lets one shared word in (w5 "drop D"). |
| R3 | Entity channel uses structural names only (paths, code spans, context files/symbols/commands). Plain query words are no longer entity names. | Plain words duplicate the lexical channel and let w5 through. |
| R4 | A relevance **gate** replaces `passes_relevance_floor`: keep a candidate if entity hit, or coverage ≥ 0.5, or cosine ≥ τs, or (coverage > 0 and cosine ≥ τw). τs = 0.40, τw = 0.25 (calibration rule §4.3). | Paraphrases share no word (baseline paraphrase hit@5 = 0.0); weak queries must stay empty. |
| R5 | Score = RRF(k = 60) × (1 + clamp(Σ adjustments, −0.30, +0.30)). Adjustments: scope closeness, status/freshness, feedback, kind (§4.4). `kind_weight` (×3/×2) and `rank::multiplier` (±45 %) leave search. | Owner: capped adjustments within ±30 %. |
| R6 | Packing: diversity cap 2 cards per file/symbol entity, then token budget (default 1,200 tokens = 4,800 B of card JSON, clamp 200–4,000), then `limit`. `more` = eligible − returned. | P§3.3. |
| R7 | Usage `fetched` counts only `/search` and `/get` (agent routes). Brief, topic and web reads never count; ranking never reads `fetched`. | A17. |
| R8 | Brief: last handoff for repo+branch+worktree, then rules/decisions/gotchas ranked by recent-file overlap, branch and feedback, then ≤ 2 preferences, inside 1,200 B. | P§3.4 L0; step-2 brief ranks by recency only. |
| R9 | Determinism: query embedding waits for the model lock (no `try_lock` fallback); every Rust tie-break uses microsecond `created_us`, then id. | Harness-found flakiness (bench.py comments). |

## 3. SQL (store/src/retrieve.rs)

Visibility for search, one fragment `searchable(alias)` with params `$1 = person`, `$P = project
ids (text[])`, loaded once per request by `SELECT array_agg(project_id) FROM project_members WHERE
person_id = $1`:

```sql
{a}.status IN ('active','stale') AND ({a}.expires_at IS NULL OR {a}.expires_at > now())
AND ({a}.owner_id = $1 OR {a}.scope = 'global' OR ({a}.scope = 'project' AND {a}.project_id = ANY($P)))
```

(`superseded` and `forgotten` never enter search. The F§1.2 `visible()` fragment stays for `/get`,
lists and the graph.)

### 3.1 Vector channel (one transaction)

```sql
SELECT set_config('hnsw.iterative_scan', 'relaxed_order', true),
       set_config('hnsw.ef_search', '100', true),
       set_config('hnsw.max_scan_tuples', '20000', true);
WITH c AS MATERIALIZED (
  SELECT m.memory_id, m.embedding <=> $2::vector AS dist
    FROM memories m
   WHERE m.embedding IS NOT NULL AND {searchable(m)}
   ORDER BY m.embedding <=> $2::vector
   LIMIT $4)
SELECT memory_id, (1 - dist)::float4 AS score FROM c ORDER BY dist, memory_id;
```

`relaxed_order` may return near-ties out of order; the outer `ORDER BY` restores exact order.

### 3.2 Lexical channel

```sql
WITH q AS (
  SELECT CASE WHEN strpos(w::text, '!') > 0 THEN w
              ELSE replace(w::text, ' & ', ' | ')::tsquery END AS query
    FROM websearch_to_tsquery('english', $2) AS w)
SELECT m.memory_id, ts_rank_cd(m.search_tsv, q.query, 32)::float4 AS score
  FROM memories m, q
 WHERE m.search_tsv @@ q.query AND {searchable(m)}
 ORDER BY score DESC, m.memory_id LIMIT $4;
```

### 3.3 Entity channel

Same SQL as step 2 with `{searchable(m)}`; names from `query_entity_names` rewritten as:
`entities::derive(&[query], &context).map(|e| e.name)` only (drop `tokenize(query)`, the raw words
and the lower-cased whole query). Empty names → channel skipped.

### 3.4 Neighbours

Step-2 SQL with `{searchable(n)}`; seeds = top 32 fused ids. Unchanged otherwise.

### 3.5 Candidate load with gate inputs

```sql
WITH q AS (SELECT coalesce(array_agg(DISTINCT lexeme), '{}') AS lx
             FROM unnest(to_tsvector('english', $3)))
SELECT {MEMORY_SELECT columns},
       (EXTRACT(EPOCH FROM m.created_at) * 1000000)::bigint AS created_us,
       CASE WHEN $4::vector IS NULL OR m.embedding IS NULL THEN NULL
            ELSE (1 - (m.embedding <=> $4::vector))::float4 END AS cosine,
       CASE WHEN cardinality(q.lx) = 0 THEN 0::float4 ELSE
         ((SELECT count(*) FROM unnest(q.lx) l WHERE m.search_tsv @@ quote_literal(l)::tsquery)::float4
           / cardinality(q.lx)) END AS coverage
  FROM memories m, q
 WHERE m.memory_id = ANY($2) AND {searchable(m)};
```

`quote_literal(l)::tsquery` matches the already-stemmed lexeme without re-stemming.

Constants (core `retrieve/hybrid.rs`): `CANDIDATES_PER_CHANNEL = 64` (was 512), `POOL = 128`
(was 200), `RRF_K = 60`.

## 4. Algorithms (core, pure)

### 4.1 Search pipeline (`Store::search`)

```
projects  = member project ids of person
lexical   = lexical_candidates(q, 64)            // (id, ts_rank)
entity    = entity_candidates(names(q, ctx), 64)  // (id, count)
vector    = vector_candidates(embed(q), 64) if model loaded
neigh     = neighbours(top 32 of fuse(lexical, entity, vector))
fused     = fuse([lexical, entity, vector, neigh]) truncate 128
rows      = load(fused ids, q, vector)          // §3.5
hits      = for (id, rrf) in fused:
              m = rows[id]?; if !filter.matches(m) continue          // kind, project/branch filters
              if !gate(GateInput{entity_hit: id in entity, coverage, cosine, has_vector}) continue
              score = rrf * (1 + adjust(m, ctx, now))
sort hits by score desc, created_us desc, id asc
cards     = pack(hits, limit, budget)            // §4.5
mark_fetched(card ids)
```

### 4.2 Gate (`core/retrieve/gate.rs`, new; replaces `filter::passes_relevance_floor` and its stop-word list)

```rust
pub const COVERAGE_MIN: f32 = 0.5;
pub const COSINE_STRONG: f32 = 0.40;   // τs
pub const COSINE_WEAK: f32 = 0.25;     // τw, only with some lexical overlap
pub struct GateInput { pub entity_hit: bool, pub coverage: f32, pub cosine: Option<f32> }
pub fn keep(g: &GateInput) -> bool {
    g.entity_hit || g.coverage >= COVERAGE_MIN
        || g.cosine.is_some_and(|c| c >= COSINE_STRONG || (g.coverage > 0.0 && c >= COSINE_WEAK))
}
```

### 4.3 Calibration rule (done once by the step-5 worker, recorded in the as-built note)

Add `bench.py --dump-scores PATH`: for every main-set question, the gold cosine and coverage; for
every weak query, the top-3 candidate cosines. If the τs/τw above miss a §1 target, set
τs = midpoint(max weak-query cosine, 4th-highest paraphrase gold cosine) when that midpoint is in
[0.30, 0.55] and the max weak cosine < the 4th paraphrase cosine; τw = τs − 0.15. If no such gap
exists, stop and report the dump (owner question) — do not change questions, gold or corpus to
pass.

### 4.4 Adjustments (`core/retrieve/rank.rs`, replaces `multiplier` for search)

```rust
pub const ADJUST_CAP: f32 = 0.30;
pub fn adjust(m: &Memory, ctx: &WorkContext, now: i64) -> f32 {
    let scope = match m.scope {
        _ if ctx.branch.is_some() && m.context.branch == ctx.branch && m.project_id == ctx.project_id => 0.10,
        Scope::Project if m.project_id == ctx.project_id && ctx.project_id.is_some() => 0.05,
        Scope::Global => -0.05,
        _ => 0.0,
    };
    let status = if m.status == Status::Stale { -0.20 } else { 0.0 };
    let fresh = if now - m.updated_at <= 30 * 86_400 { 0.05 } else { 0.0 };
    let net = m.usage.helpful as f32 - m.usage.wrong as f32;
    let used = (0.05 * net).clamp(-0.10, 0.10);
    let kind = match m.kind {
        Kind::Rule | Kind::Decision => 0.10, Kind::Gotcha | Kind::Procedure => 0.05,
        Kind::Fact | Kind::Preference => 0.0, Kind::Note => -0.05, Kind::Handoff => -0.10,
    };
    (scope + status + fresh + used + kind).clamp(-ADJUST_CAP, ADJUST_CAP)
}
```

Delete `hybrid::kind_weight`; delete `rank::multiplier` once `brief.rs` stops using it (§4.6).
`status_after_wrong` stays.

### 4.5 Packing (`core/retrieve/pack.rs`)

```rust
pub const BUDGET_DEFAULT: usize = 1200;           // tokens
pub fn pack(hits: Vec<Hit>, limit: usize, budget_tokens: usize) -> Cards {
    let budget = budget_tokens.clamp(200, 4000) * 4;  // bytes (bytes / 4 estimate, as the bench)
    let (mut out, mut deferred, mut used) = (vec![], vec![], 0usize);
    let mut per_entity: HashMap<&str, u8> = HashMap::new();
    for h in &hits {                                  // pass 1: diversity
        let keys = file_and_symbol_names(&h.memory);
        if keys.iter().any(|k| per_entity.get(k).copied().unwrap_or(0) >= 2) { deferred.push(h); continue; }
        if !try_add(&mut out, &mut used, budget, limit, h) { break; }
        for k in keys { *per_entity.entry(k).or_default() += 1; }
    }
    for h in deferred { if !try_add(&mut out, &mut used, budget, limit, h) { break; } }  // pass 2
    let more = hits.len() - out.len();
    Cards { results: out, more }
}
// try_add: card = Card::from(hit) with score normalised to the top hit; cost = compact JSON len + 1;
// refuses when out.len() == limit or (used + cost > budget and !out.is_empty()).
```

`Card.score` normalisation (top = 1.0, 3 decimals) is unchanged from S§3.1.

### 4.6 Brief (`core/retrieve/brief.rs`, rewritten; caps from C§2.2)

Store query (`Store::brief`): visible, `status = 'active'`, and one of:
handoff owned by the person with `repo_branch = ctx.branch AND repo_worktree IS NOT DISTINCT FROM
ctx.worktree AND project_id IS NOT DISTINCT FROM ctx.project_id`; rule/decision/gotcha with
`project_id = ctx.project_id`; preference owned by the person. `LIMIT 300`, with entities.

```
handoff = newest matching handoff (created_us desc, id)           -> section ≤ 400 B
for each rule/decision/gotcha m:
   overlap = |{f in m.file_entities : f in recent || parent_dir(f) in parent_dirs(recent)}|
   s = base(m.kind)            // rule 3, decision 3, gotcha 2
     + 2 * min(overlap, 3)
     + 1 if m.context.branch == ctx.branch (and Some)
     + 0.5 * clamp(helpful - wrong, -2, 2)
     + 0.5 if now - updated_at <= 14 d
   skip m if m.context.branch is Some and != ctx.branch and != project default branch
order by s desc, created_us desc, id; add items while total ≤ 1,200 B
preferences: newest 2 within 240 B
```

`recent` = request `recent_files` (C§2.2). JSON keys: `last_handoff`, `project` (items
`{id, kind, title, summary}`), `preferences`. Fence and "data, not instructions" label unchanged.
The default branch comes from `projects.default_branch`; NULL means "main or master".

### 4.7 Determinism

- `LocalEmbeddings::query`: replace `try_lock` with `lock()` inside `spawn_blocking`; a poisoned
  lock or inference error returns `None` and logs (unchanged message). Embedding jobs hold the
  lock for one batch (`EMBED_BATCH`), so the wait is bounded.
- `Memory` gains `#[serde(skip)] pub created_us: i64`, filled by every `MEMORY_SELECT`
  (`(EXTRACT(EPOCH FROM m.created_at)*1000000)::bigint`); every Rust sort that compared
  `created_at` compares `created_us`.

## 10. Risks

- MiniLM cosine for some paraphrases may sit below the weak-query noise; §4.3 stops for an owner
  decision rather than overfitting.
- Iterative scans can visit up to `max_scan_tuples` (20,000) rows for a person with very few
  visible memories; fine at small-team scale, and the planner may choose the btree path for very
  selective filters (still exact).
- Moving embeddings onto `memories` makes status updates rewrite a ~1.6 KB row; updates are rare
  (feedback goes to `usage`).
- Dropping plain words from the entity channel can lose recall for single-word queries that
  matched a `term` entity; the lexical channel covers them (coverage = 1.0 for one-word queries).

## 11. As built — chunk 5a (schema + channels)

Built on branch `0.1.6` after `1561812`. The holdout fixture is its own first commit (`4164017`), before
any channel or ranking change; its paraphrase self-check passes (no shared content word with any gold).
Ranking, gate, packing, brief, server routes, bench flags and calibration are chunk 5b.

What is in:

- `migrations/0003_retrieval.sql` exactly as §2; pgvector 0.8.7 in `pgvector/pgvector:pg17`, so iterative
  scans are available. `embed.rs`, `consolidate.rs` and `forget` read and write the three new `memories`
  columns; `memory_embeddings` is gone from `crates/` and `scripts/` (`rg` clean).
- `memory::searchable(alias, me, projects)` and `Store::member_projects`. Every channel takes the
  project-id array (`$3`) as the spec's `$P`. `lexical_sql()` and `vector_sql()` are `pub` so the plan
  tests explain the exact statement the channel runs.
- Lexical channel (OR with a negation guard), vector channel (one transaction, `relaxed_order`,
  `ef_search 100`, `max_scan_tuples 20000`, visibility in the scan, outer re-sort), entity channel
  (structural names only, skipped when empty), neighbour channel (`searchable(n)`, seeds = top 32,
  now `pub`), and `Store::load_candidates` returning `Candidate { memory, cosine, coverage }`.
- `CANDIDATES_PER_CHANNEL = 64`, `POOL = 128` (in `hybrid.rs`), `Memory.created_us` filled by every
  `MEMORY_SELECT` (now `MEMORY_COLUMNS` + FROM), graph and brief sorts and the search hit sort use it.
  `LocalEmbeddings::query` waits on `lock()`.
- Still step-4 behaviour on purpose (5b replaces them): `passes_relevance_floor`, `kind_weight`,
  `multiplier`, `pack::cards`, the old brief. `rank` uses the new channels and the candidate load but
  does not read `cosine` or `coverage` yet.

Deviations:

1. **Coverage SQL.** `m.search_tsv @@ quote_literal(l)::tsquery` breaks on a lexeme with a backslash
   (`quote_literal` returns `E'..'`). Coverage is `count(lexemes of search_tsv that are in the query's
   lexeme set) / cardinality`, which is the same number without quoting and is cast to `float4`.
2. **Coverage of w5 is 0.25, not 0.33.** "guitar tuning for drop D" has four lexemes (`guitar`,
   `tune`, `drop`, `d`; `d` is not an English stop word). The test asserts 0.25. The gate (coverage
   ≥ 0.5) behaves the same.
3. **`pending_embeddings` / `enqueue_missing_embeddings` use `embedding IS NULL` only.** The current
   `embedding_source` hash needs the entities and `embedding_text` in Rust, which SQL cannot compute; a
   changed text is re-embedded by the embed job that its save queues (`upsert_embedding` rewrites when
   the hash or model differs). The step-4 behaviour was the same (`NOT EXISTS` row).
4. **Public channel signatures changed:** `lexical_candidates`, `entity_candidates`,
   `vector_candidates` take `(person, projects, ..)` instead of loading the projects themselves, so
   `search` loads them once.
5. **Superseded is excluded in SQL** (`searchable`), so `rank` no longer checks `Status::Superseded`.
6. **Tie-break order.** Ids are random per run, so a tie broken by id is not reproducible. Channel SQL
   orders ties by `created_at DESC, memory_id`; `fuse` keeps the caller's order for equal scores
   (first channel that listed the id for equal fused scores) instead of sorting by id; the neighbour
   channel keeps first-seen order. This is wider than the spec's "Rust tie-breaks use `created_us`"
   and was needed for two bench runs to match.
7. **bench.py `settle()` also waits for the `embed` and `consolidate` jobs.** Embeddings alone were not
   enough: consolidation supersedes and links near-duplicates after the vector exists, and a search
   that raced it made two otherwise identical runs differ (6 of 35 questions reordered in the
   low ranks). With the wait, two runs give identical `per_question_memory_search`, holdout and
   zero-hit rows. The 1-second sleep between saves is removed (brief orders by `created_us`).
8. `bench.py` already loads and reports the holdout (`recall_holdout`, `zero_hit_holdout`) and
   self-checks its paraphrases; the gates and flags in §5 items 2–5 are 5b.
9. Test names differ where one test covers two spec names: `vector_filter_inside_scan`,
   `plans_use_the_hnsw_gin_and_entity_indexes` (covers `vector_plan_uses_hnsw` and
   `lexical_plan_uses_gin`), `lexical_reads_and_as_or_with_coverage_unless_negated` (covers
